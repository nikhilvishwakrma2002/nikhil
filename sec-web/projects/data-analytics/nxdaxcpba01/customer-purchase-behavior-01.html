Pipeline

From a raw CSV to a Streamlit app in five steps.

The notebook prepares the data and saves the models. The app then reads those files and presents them across six pages.

01

Source

302,010 rows across 30 fields, covering transactions, customers, products, geography and ratings.

02

Clean

Convert types, fill gaps, drop four exact duplicates and derive a year field from the date.

03

Analyze

Group Total_Amount by month, category, gender, brand and segment, then build RFM features for each customer.

04

Model

K-Means with five clusters (random_state 42) and a Random Forest with 100 trees for spending.

05

Explore

Six Streamlit pages with Plotly charts, filters, segment views and prediction inputs.

The six app pages

Home introduces the platform. Dashboard filters by date, country, gender and category, and summarizes amount, customers, orders and ratings. Customer Segmentation shows K-Means clusters and RFM comparisons. Predictions estimates spending from age, purchase count and rating. Business Insights ranks category, brand and country totals. About describes the project.

Built with

Python, Pandas and NumPy for data work. scikit-learn for K-Means and Random Forest. Joblib for saving models, Plotly for interactive charts and Streamlit for the app. Matplotlib and Seaborn appear in the notebook.

Model

The spending model is a starting benchmark, not a finished forecast.

A Random Forest estimates Total_Amount from Age, Total_Purchases and Ratings. It is trained on a random 80/20 split with seed 42, and the fitted model is saved with Joblib for the Predictions page.

What is still missing

No median baseline, cross-validation, R², error distribution or time-based test is reported. The model has not been shown to work on later transactions, so treat ₹656.45 as the first benchmark to beat.

Limitations

Known limitations, and what would fix each one.

Customer identity

Zero-filled IDs merge unrelated records into one person. Keep missing IDs empty or label them unknown, and exclude them from customer counts and RFM.

Missing source data

The Dataset folder in the archive is empty. The notebook expects customer_purchase_data.csv, the app expects cleaned_customer_purchase_data.csv, and segmentation expects rfm_customer_segments.csv. Restore authorized copies before a clean run.

Validation

The model uses one random holdout split. Add a mean or median baseline, cross-validation, R² and a time-based test to show whether it generalizes.

Personal data

The source includes names, emails, phone numbers and addresses. Analysis and prediction do not need them, so remove them from analytical extracts and limit access to raw data.

Interface checks

Some saved screenshots show a visible “undefined” label beside chart sections. Check every chart panel in a clean launch before a live demo.

Wording

The README describes the app as AI-generated. The insight text is rule-based and no language model is connected, so the label should say that plainly.

Imputed values, not observed ones. Before totals, means and the model were calculated, blank values were filled. 350 Total_Amount values (0.12%) were replaced with the column median, and so were 361 Total_Purchases, 184 Ratings and 173 Age values. 359 blank dates were carried forward from the row above. Filled Total_Amount values are part of the ₹412.9M total and the model’s target. Filled Age, Total_Purchases and Ratings values are model inputs.
